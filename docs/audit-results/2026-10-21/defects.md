# Реестр дефектов и изменений аудита

Дата: 21.10.2026. Baseline: `d542fe8`. Статус «исправлено» означает код кандидата и указанную проверку; он не означает выпуск в production. Общие ограничения и результаты нагрузки — в [REPORT.md](REPORT.md).

## Исправленные дефекты

| ID / приоритет | Сценарий и последствие | Исправление | Доказательство |
| --- | --- | --- | --- |
| D01 / P1 | JWT сотрудника после смены PIN/общего отзыва продолжал менять позиции и остатки напрямую; чтение меню могло уже запрещаться | Общая проверка точки, активности и staffVersion перед защищёнными staff-запросами | Реальный Appwrite: baseline допускает запись, кандидат возвращает 401. Локально проверены все 12 видов записей и персональная cookie |
| D02 / P1 | Отзыв ссылок обрабатывал первые 100/200 строк; оставшаяся старая ссылка могла получить новую сессию | Общий helper обрабатывает все страницы активных ссылок; ротация сохраняет только свою новую ссылку | Реальный Appwrite: 101/rotate, 201/revoke-all, 501/общий отзыв — старых активных ссылок 0; повторный вход старой ссылкой 401. Локально все 3 маршрута × 101/201/501 |
| D03 / P2 | Два одновременных завершения одного QR создавали разные активные токены; конкурирующие точки могли обе получить ссылку | Уникальная детерминированная строка Appwrite используется как атомарное закрепление; повтор для той же точки возвращает прежний результат | Реальный Appwrite: одинаковая ссылка у повторов, один токен; конкурирующие точки получают 200/409 |
| D04 / P2 | Частично выполненное подключение и повтор могли создавать лишний токен; повтор не должен возвращать к жизни отозванный экран | Восстановление по ранее созданной строке токена, проверка точки/секрета/active, запрет реактивации | Реальный Appwrite: заранее созданное промежуточное состояние завершено без добавления токена; повтор после отзыва 409. Локально инъекция ошибки до записи complete |
| D05 / P2 | Два `+1` из нулевого остатка записывали два события доступности при одном фактическом переходе; абсолютный PATCH пересекался с adjust | Переход ±1 определяется по результату атомарной операции; PATCH/adjust/bulk/delete используют общую очередь позиции | Реальный Appwrite: из 0 получается 2 и одно событие; отрицательный остаток запрещён, верхняя граница даёт 409; PATCH+adjust дают одно событие. Очередь действует в одном API-процессе |
| D06 / P2 | Разный регистр/пробелы логина и произвольный username у PIN-входа создавали разные ключи ограничения попыток | Канонизация логина/кода; у PIN-входа посторонний username не участвует в ключе. Лимиты и окна сохранены | Локальный HTTP: PIN, staff-password и hub-password — пять отказов 401, шестая попытка 429 независимо от варианта написания |
| D07 / P2 | Временная ошибка чтения Appwrite трактовалась как отсутствие аккаунта и отзывала действительную сессию | Только Appwrite 404 означает отсутствующую запись; прочие ошибки проходят как серверный отказ | Локальные HTTP-инъекции: ошибка upstream → 500, следующий запрос той же сессии → 200; отсутствующие точка/аккаунт → 401 |
| D08 / P2 | При усилении staff-guard посторонняя устаревшая staff-cookie могла блокировать независимый вход экрана по валидной ссылке | Точное исключение публичного `/auth/display`; защищённые staff-записи остаются под guard | Локальный HTTP и реальный кандидат: вход экрана 200, защищённая staff-запись с той же старой cookie 401. Baseline-группа также проверяет отзыв staff; её падение не доказывает отдельный baseline-сбой входа экрана |
| D09 / P2 | Повторный Enter/клик, поздний ответ после выхода, потерянный ответ записи или обрыв тела HTTP 200 могли приводить к повтору/устаревшему состоянию; повтор CSV — к дублям или неверному наличию Android | Синхронная блокировка изменений, поколения сессии, ограничение времени запроса, явный неопределённый результат без автоповтора; свежий снимок перед повтором CSV, ошибки по строкам, остановка при 401; Android учитывает stockQuantity | Web API/component и Android unit-тесты. Конкретный физический Android/старый ТВ и длительный реальный сетевой сбой этим набором не доказаны |

Приоритеты: P1 — нарушение отзыва доступа; P2 — ошибка согласованности, восстановления или статистики. Группы D03/D04 относятся к одному жизненному циклу pairing; это не статистика количества независимых инцидентов.

## Как читать 12 групп реального прогона

Проверены сохранённые JSON: baseline — **1/12 прошла, 11 не прошли**, кандидат — **12/12 прошли**; очистка временных данных прошла в обоих случаях. Это не «11 разных багов»: набор охватывает **четыре основных семейства** (отзыв staff, пагинация отзыва экранов, жизненный цикл pairing, статистика конкурентных остатков), добавленную возможность синхронизации и проверки отсутствия регрессий.

| Группа / порядок в JSON | Baseline | Кандидат | Связь с дефектом и граница вывода |
| --- | --- | --- | --- |
| G01 — staff version + изоляция | 403 вместо 200 | Прошла | Добавлен staff-доступ к `/menu/version`. Последующие проверки изоляции в этой baseline-группе не достигнуты; у кандидата пройдены |
| G02 — отозванная/отключённая staff-сессия | Запись 200 вместо 401 | Прошла | D01: запись со старой сессией допускается |
| G03 — вход экрана при старой staff-cookie | Защищённая staff-запись 200 вместо 401 | Прошла | Пересечение с D01 и контроль D08. Падение baseline относится к записи; отдельный отказ входа экрана им не доказан |
| G04 — ротация 101 ссылки | Старые ссылки остались активны | Прошла | D02: граница первой страницы 100 |
| G05 — revoke-all 201 ссылки | Старые ссылки остались активны | Прошла | D02: граница прежнего лимита 200 |
| G06 — общий отзыв 501 ссылки | Старые ссылки остались активны | Прошла | D02: обработка нескольких страниц |
| G07 — параллельное завершение QR + повтор | Получены разные URL | Прошла | D03: один QR создавал больше одного результата |
| G08 — конкурирующие точки для одного QR | Нет требуемой пары 200/409 | Прошла | D03: тот же конфликт жизненного цикла pairing |
| G09 — незавершённое закрепление pairing | Возвращён новый URL вместо закреплённого | Прошла | D04: проверка контракта восстановления из заранее созданного промежуточного состояния; это не аварийный stop сервера |
| G10 — два `+1` и статистика/границы | Нет единственного события перехода | Прошла | D05. Baseline остановился до дальнейших проверок min/max; кандидат прошёл их |
| G11 — абсолютный остаток одновременно с adjust | Не выполнено требование одного перехода | Прошла | D05: другая конкурирующая комбинация того же семейства |
| G12 — московские сутки, эпохи и изоляция статистики | Прошла | Прошла | Сохранённое корректное поведение, не новый дефект |

Внутри группы первая неудачная проверка останавливает оставшиеся assertions. Поэтому падение группы baseline не следует описывать как провал всех её внутренних условий. D06/D07/D09 дополнительно подтверждены локальными HTTP/component/JVM-тестами; этот реальный набор не является отдельным доказательством их полного поведения под нагрузкой.

## Добавленная возможность

Staff-клиент теперь может читать `/api/menu/version`, а кабинет синхронизирует меню с изменениями другого сотрудника. Baseline для этого маршрута с ролью staff возвращал 403, кандидат — 200. Это новое требование синхронизации и его совместимость, а не самостоятельная уязвимость baseline. Синхронизация двух браузерных кабинетов подтверждена; отдельный нагрузочный staff-polling supplement не запускался до остановки пользователем. Точные границы указаны в основном отчёте.
