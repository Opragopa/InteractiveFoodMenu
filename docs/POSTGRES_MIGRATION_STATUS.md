- Добавлена отдельная Compose-задача `migration`, которая по умолчанию выполняет preflight и использует Appwrite как источник. Поднятие рабочего API и импорт не происходят автоматически.
- Импортёр проверяет счётчики исходных страниц и наличие изображений блюд, дополнительно к прежней проверке полей, хэшей, связей, файлов, пустой цели и транзакционному откату.
- Подготовлен `scripts/backup-appwrite-migration.ps1`: dump исходной БД, read-only архив storage, приватные конфигурации, исходные runtime-образы, Compose override для отката, SHA-256 и ограниченный ACL. Скрипт сам не останавливает сервисы. Подтверждение `-SourceFrozen` обязательно; запущенный прикладной API блокирует резервное копирование до любых записей.
- Обновлён [порядок переноса и отката](POSTGRES_MIGRATION.md), включая разделение source preflight, резервной копии, импорта и переключения провайдера.

## До переноса рабочих данных

На read-only discovery в 09:20 МСК 22.10.2026 рабочие `appwrite`, `appwrite-postgresql`, `appwrite-redis` были остановлены, рабочий API — `unhealthy`, `/ready` — не готов. Это состояние существовало до остановки тестового стенда. Рабочая инфраструктура в рамках подготовки не перезапускалась.

1. Восстановить доступность исходного Appwrite и проверить `/ready` рабочего API.
2. Согласовать окно остановки всех записей, включая дополнительные API, задания и Appwrite Console.
3. Снять резервную копию **рабочего** Appwrite, storage и конфигураций; сохранить вне хоста и подтвердить восстановление на изолированном экземпляре. Синтетическая репетиция этого не заменяет.
4. Подготовить пустую целевую PostgreSQL, приватные секреты и проверенную сборку. Выполнить preflight, затем импорт с остановленными писателями и проверить отчёт.
5. Переключить API, проверить существующие пароли/сессии/файлы, статистику и физические экраны, резервное копирование новой БД. Открыть обычные записи после приёмки.

Рабочая резервная копия, перенос рабочих данных, переключение провайдера, публикация в Git и deployment **не выполнялись**. Windows backup script проверен на синтаксис и защиту; его полный сценарий резервного копирования рабочих данных ещё не исполнялся.
